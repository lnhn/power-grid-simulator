# 皮肤 2.0 与 3D 数字孪生：规划

> 目标：同一张电网，既能在 2D 单线图里画和算，也能在 3D 里"看到现场"；风格（皮肤）由用户选，含义（带电/失电/冲突）永远不变。

## 一、现状盘点（动手前的基线）

| 层 | 现在是什么 | 缺口 |
| --- | --- | --- |
| 皮肤 | `lib/skins/tokens.ts`：3 套皮肤（industrial / schematic / paper）× 明暗，只有颜色、圆角、字体 | 只改"配色"，不改"形态"；元件卡片长相固定 |
| 符号集 | `SymbolSet`：iec / gb / simple 三种 | 只在图标层面，卡片外形没跟着变 |
| 元件 | 5 个 ReactFlow 自定义节点组件（电源/开关/母线/变压器/负荷） | 视觉逻辑分散在各组件内，加皮肤要改 5 处 |
| 运行态 | 求解器 `GridSolveResult` + `buildNodeRuntime` → 每节点带电/电压/负荷/母联方式 | 只有 2D 叠加，没有第三维投影 |
| 3D | 无。依赖里没有 three | 全新增 |

**要守住的两条铁律**

1. 皮肤只改表面（配色、材质、形态、字体），不改语义色：带电 `#16a34a`、失电 `#94a3b8`、冲突 `#dc2626`。
2. 皮肤不碰 `lib/grid`（求解、校验、拓扑）；3D 也只读求解结果，不自己算电。

## 二、皮肤 2.0：从"配色包"升级为"组件规格包"

### 2.1 数据模型

把现在的 `SkinTokens` 扩成 `SkinSpec`：

```ts
type SkinSpec = {
  id: SkinId
  meta: { name: string; description: string; thumbnail?: string }
  color:  SkinTokens            // 现有调色板，保留
  shape: {                      // 新增：形态维度
    nodeStyle: 'card' | 'compact' | 'terminal'  // 卡片 / 紧凑条 / 端子式
    radius: number              // 圆角
    borderWidth: 1 | 2
    shadow: 'none' | 'soft' | 'hard'
    iconFrame: 'tile' | 'circle' | 'bare'   // 图标底板
    labelAlign: 'stack' | 'inline'
  }
  wire: {                       // 连线风格
    style: 'orthogonal' | 'straight'
    width: number
    animated: boolean
  }
  symbolSet: SymbolSet          // 皮肤默认符号集（用户仍可单独覆盖）
  view3d: {                     // 3D 皮肤（见第三节）
    material: 'pbr-steel' | 'flat-graphite' | 'matte-paper' | 'wireframe'
    edgeLine: 'none' | 'thin' | 'glow'
    ambient: number
    background: 'gradient' | 'flat' | 'grid'
  }
}
```

### 2.2 落地方式

- 新建 `lib/skins/spec.ts`：把三套现有皮肤改成 spec；新增皮肤只需追加一个对象 + 一张预览图。
- 新建 `components/nodes/NodeShell.tsx`：所有元件卡片走同一个外壳（底色、描边、圆角、阴影、图标框、标签排布），元件只负责"身体"（符号 + 参数）。以后再换皮肤只改外壳，不改 5 个组件。
- `SymbolIcon` 保持独立维度：皮肤给默认符号集，用户在设置里可覆盖。
- 设置页（`app/settings`）加"皮肤预览"：每种皮肤一张实时渲染的小卡片 + 3D 材质小球，选中即生效（localStorage `pg.skin` / `pg.mode`）。

### 2.3 首批皮肤（建议）

| 皮肤 | 适合谁 | 形态要点 |
| --- | --- | --- |
| industrial（保留） | 控制室大屏 | 卡片 + 冷灰钢构 + 深蓝强调 |
| schematic（保留） | 电气工程师 | 紧凑条 + 等宽字体 + 细线框 |
| paper（保留） | 交底打印 | 卡片 + 暖白 + 无阴影 |
| **terminal**（新） | 手机/平板现场 | 端子式窄条、只有状态灯与名称，信息密度最高 |
| **dark-neon**（新） | 值班室夜间 | 深底 + 发光描边（仅 2D 装饰，语义色不变） |
| **mono-blue**（新） | 极简偏好 | 单色蓝 + 纯线性图标 + 1px 描边 |

## 三、3D 数字孪生：用 three.js 画"现场"

### 3.1 定位（先把话说清楚）

这里的"数字孪生"是**可视化孪生**：把已有的拓扑与求解结果映射成可辨认的三维设备场景，让人一眼看出"哪台柜子带电、哪路在带负荷、母联是合是分"。
不是**仿真孪生**：不做热场、气流、振动、寿命预测。后者要接入实测点与模型，属于下一阶段（M9+），不混在这一步做。

### 3.2 技术选型

- `three` + `@react-three/fiber` + `@react-three/drei`（fiber v9 支持 React 19）。
- 不做裸 three 手写渲染循环：场景要跟 React 状态（求解结果、选中、皮肤）同步，声明式写法省事且不易漏清理。
- Next 16 下 3D 组件必须 `dynamic(() => import(...), { ssr: false })`，独立 chunk 懒加载（three 约 600KB gzip，不进主包）。

### 3.3 数据契约（关键）

```ts
// lib/twin/scene.ts —— 纯函数，可单测
buildTwinScene(nodes, edges, result): {
  devices: Array<{
    id: string
    kind: 'source' | 'busbar' | 'breaker' | 'tie' | 'transformer' | 'load'
    box: { w: number; h: number; d: number }   // 尺寸（米）
    at: { x: number; y: number; z: number }    // 场景坐标
    state: { powered: boolean; conflict: boolean; loadKw?: number; sourceKw?: number; tieMode?: string }
    label: string
  }>
  cables: Array<{ id: string; from: string; to: string; kw: number; powered: boolean }>
}
```

坐标映射规则（保证"孪生"一致，不做第二次布局）：

- 2D 的 `position.x` → 3D 的 `x`；2D 的层级（`layout.ts` 算出的 rank）→ 3D 的 `z`（纵深），同排左右不变。
- 比例：1 网格单位 ≈ 1 米，母线长条 6m，开关柜 1.2×2.2×0.8m，负荷柜 1.5×2×1m。
- 后续若要真实厂房坐标，新增可选字段 `data.plantPosition {x,y,z}`，有则用、无则用映射——不阻塞现在。

### 3.4 几何来源（第一版程序化，不依赖美术资产）

| 元件 | 3D 表现 |
| --- | --- |
| 电源 | 进线柜 + 顶部绝缘子 + 铭牌（380V / 出力 kW） |
| 母线 | 悬空铜排（长条 + 端帽），带电时自发光条带 |
| 断路器/母联 | 柜体 + 可见刀闸（合=闭合角度，分=断开），母联两端各接一段母线的横向连桥 |
| 变压器 | 双柜体（高压侧/低压侧）+ 散热片阵列 |
| 负荷 | 按 subType 换外形（泵=立式泵体、风机=蜗壳、加热器=筒体、压缩机=箱式机组） |

所有柜体用同一套参数化组件（Box + 细节 + 材质），设备类型只决定"参数组合"。这样既不依赖建模，又能一眼区分设备。

### 3.5 运行态在 3D 里怎么表达

- 设备：带电 = 语义绿描边 + 面板指示灯亮；失电 = 灰、灯灭；冲突 = 红闪。
- 电缆/母排：带电走"流光"粒子（沿路径等距小光点），失电为灰线；这是 3D 里最直观的"电在流"。
- 母联：刀闸合上时两端铜排连成一线，断开时中间留空气隙 + 灰色虚影，避免"合了看不出、断了也看不出"。
- HUD 与 2D 完全一致：总负荷、分段数、母联方式、图例文案复用同一份 `snapshot.result`，不许两套口径。

### 3.6 交互

- 点击设备 → 相机轻推聚焦（`CameraControls` 的 `fitToBox`），右侧面板显示该设备设计参数 + 运行态（复用编辑页那块"运行态"信息）。
- Hover：外轮廓高亮（非改色），避免与"带电"混淆。
- 视角预设：等轴俯视（默认）、正视（看柜门）、俯视（看母排布局）；一键复位。
- 运行态开关、皮肤切换在 3D 内同样有效（3D 皮肤只换材质光照，不换语义色）。

### 3.7 性能预算

- 目标：200 台设备、60fps（集显笔记本）。手段：柜体走 `InstancedMesh`、阴影只留一盏方向光 + 接触阴影、远处 LOD 简化、`dpr` 上限 2、不可见区域 `frameloop="demand"`。
- 超过 400 台设备时降级：关闭流光与阴影，只保留语义色。

## 四、分期（每期都可独立验收）

| 期 | 内容 | 产出 | 大致体量 |
| --- | --- | --- | --- |
| **P0 皮肤 2.0** | SkinSpec + NodeShell + 设置页预览 + 新增 2 套皮肤 | 2D 换皮肤不再改组件；新增皮肤零代码 | 1 天 |
| **P1 3D 只读孪生** | `/grid/[id]/twin` 路由；程序化柜体/母排；语义色 + 选中面板；与 simulate 页共用求解 | 能在 3D 里看出全厂设备与带电状态 | 2–3 天 |
| **P2 潮流与动作** | 流光粒子、刀闸开合、负荷启停、HUD 对齐 | 3D 里"看得出电在流、开关在动" | 1–2 天 |
| **P3 3D 编辑** | 3D 拖拽改 x/z 并写回 position；区域/楼层分组 | 2D 画完直接在 3D 摆位 | 1–2 天 |
| **P4 资产化** | 每类设备支持 GLB 替换程序化外形；皮肤包目录化（可导入） | 想要真实外观时可挂模型 | 按需 |

**建议顺序**：P0 → P1 → P2，先让"换皮肤"这件事一次性做扎实，再上 3D。理由：3D 的材质/形态要复用皮肤 spec，如果皮肤还是散在 5 个组件里，3D 会跟着一起散。

## 五、风险与取舍（先说清楚，免得后面返工）

1. **构建体积**：three 只能在 3D 路由懒加载，主包不许涨。验收标准：首页/编辑页 chunk 体积不变。
2. **程序化几何的"廉价感"**：第一版难免像"盒子开会"。对策是材质、描边、灯光和铭牌信息量，而不是堆模型；P4 再补资产。
3. **数据一致性**：3D 与 2D 必须同一份求解结果；任何"3D 自己算一遍"的写法都禁止。
4. **移动端**：3D 在低端平板可能掉帧，默认给 2D；3D 作为可选入口并给出"性能降级"档。
5. **范围蔓延**：仿真孪生（热/流/寿命）不在本期，避免目标漂移。

## 六、已定方向（2026-11-20）

1. **3D 入口**：并入 `simulate` 页，用「2D 单线图 / 3D 现场」视图切换。three 只在切到 3D 时 `dynamic import`，2D 默认视图不加载三维包。
2. **3D 范围**：只做配电室——电源柜、开关柜（含母联联络柜）、母线铜排、变压器柜。负荷设备只在 3D 里以「接到哪段母线」的轻型标识出现，不建模。
3. **顺序**：先皮肤 2.0（已于 v2.10.0 落地），再 3D 只读孪生。

据此，P1 的验收口径调整为：`simulate` 页可在 3D 里看到配电室四类设备与带电状态，切换视图不影响 2D 编辑。
